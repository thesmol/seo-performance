# seo-performance — задания №6, №9

Практические работы по дисциплине «SEO — оптимизация портальных решений».

В задании №9 этот репозиторий содержит сравнение приложений с jQuery и без неё. Часть Schema.org и Open Graph находится в [seo-trekking](https://github.com/thesmol/seo-trekking).

## Публикации и исходники

- №6: [GitHub Pages](https://thesmol.github.io/seo-performance/task-06/), снимок этапа в `task-06/`.
- №9: [GitHub Pages](https://thesmol.github.io/seo-performance/task-09/native.html), снимок этапа в `task-09/`.
  [Вариант с jQuery](https://thesmol.github.io/seo-performance/task-09/jquery.html).

Каждая папка этапа содержит свои ресурсы и не требует файлов последующих заданий.

## Локальный запуск

```sh
npm ci
npm run dev
```

Откройте адрес, показанный Vite (обычно `http://127.0.0.1:5173/`). Для AJAX и XML используйте HTTP, а не `file://`.

Для сборки и проверки статической публикации:

```sh
npm run build
npm run preview
```

Нужен Node.js 20.19+ или 22.12+. Сборка Vite сохраняет исходные HTML, CSS, JavaScript, XML и медиа без изменения: это важно для сравнения размеров jQuery, AMP-валидации и самостоятельности этапов. Для замеров используйте `preview`, потому что `dev` добавляет служебный клиент Vite.

### Задание №6

```text
Написать ajax-приложение, которое считывает из внешнего rss-файла данные и выводит на экран заголовки и текст новостей. Также на экран должно выводится время обработки и вывода данных.

    Осуществить конвертацию rss-файла в формат json с помощью любого online-конвертера, например, http://www.utilities-online.info/xmltojson/. Написать ajax-приложение, которое считывает из внешнего json-файла данные и выводит на экран заголовки и текст новостей. Также на экран должно выводится время обработки и вывода данных.

    С помощью генератора rss-лент (открывается в браузере) создать ленты из 100,200,500,1000 итд (при необходимости) новостей. С помощью кода из задачи 1 построить таблицу зависимости времени обработки xml-данных от числа новостей. Сконвертировать эти rss-ленты в формат json. С помощью кода из задачи 2 построить таблицу зависимости времени обработки json-данных от числа новостей. На основании полученных таблиц построить сравнительный график зависимости времени обработки данных разных форматов от числа новостей. Таблицы и график можно строить в Excel. Сделать выводы о производительности javascript при обработке xml- и json-данных.

ВАЖНО! Алгоритмы и формат вывода данных в задачах 1 и 2 должны совпадать. В этих задачах НЕ допускается использование javascript-фреймворков (jquery итп)
Исходные данные: генератор rss-лент (https://disk.yandex.ru/d/w-d4vZhT0C2YzQ)

Примеры: подгрузка и вывод xml- и json=данных (https://disk.yandex.ru/d/2YJRhzoCSfiqUQ)


Приложение: addons/task6/...
```

### Задание №9

```text
Оценка необходимости применения фреймворков на простых задачах.
    Измерить время от начала загрузки страницы (!) до окончания отображения выводимых данных с использованием и без использования фреймворка jQuery на медленных соединениях/мобильных устройствах. Для оценки времени рекомендуется использовать метод performance.now(). Результаты оформить в виде графика в Excel.

    Для эмуляции медленных соединений в Google Chrome в режиме WebDeveloper(F12) в пункте Network использовать режим "Slow 3G". В браузере Firefox также есть подобные настройки.

    В качестве задачи использовать код решения задания №6 по обработке и выводу информации из xml- или json-данных. Целесообразно проводить измерения для файлов размером от 0.01-0.5МБ (от 10 до ~200 новостей).

    Исходные данные: Фреймворк jQuery(https://jquery.com/), пример подсчета времени от начала загрузки (https://yadi.sk/d/1ULKkFQtzSP1AA)

    Семантическая разметка страницы с помощью Schema.org и Open Graph
        Для сверстанного в задании №4 (контрольное) шаблона необходимо выделить 2-3 подходящих типа данных из поддерживаемых schema.org, и описать эту информацию с помощью соответствующих элементов микроразметки.
        Для сверстанного в задании №4 (контрольное) шаблона необходимо сформировать opengraph-описание страницы.

    Результат должен проходить проверку валидаторов микроразметки, например, https://webmaster.yandex.ru/tools/microtest/, https://developers.facebook.com/tools/debug/
```
